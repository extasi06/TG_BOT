# Отчёт по модулю обратной связи
## Чат-бот «Вопросы математики»

### 1. Цель модуля

Реализовать **автономную** систему проверки ответов и педагогической обратной связи без выдачи готового решения, с измерением:

1. снижения повторяемости одной и той же ошибки;
2. роста доли верных ответов на аналогичных задачах после подсказки;
3. качества объяснений (понятность, полезность, отсутствие «спойлера»).

---

### 2. Архитектура

```
Ответ ученика
    → validators (нормализация, дроби)
    → ErrorClassifier (правила + expression_parser)
    → FeedbackEngine (шаблоны из feedback_templates)
    → PracticeTracker → SQLite (error_learning, feedback_log, attempts)
```

**Смешанный подход «правила + разбор выражений»:**

- сопоставление с `error_patterns` в банке задач;
- эвристики (знак, числитель без знаменателя, порядок действий);
- вычисление выражения из условия (PEMDAS vs слева направо) через AST.

---

### 3. Классификатор ошибок

| Код | Описание |
|-----|----------|
| `wrong_common_denominator` | Неверное приведение к ОЗ |
| `added_numerators_only` | Сложили только числители |
| `sign_error` | Ошибка знака |
| `order_of_operations` | Нарушен порядок действий |
| `fraction_addition` | Неверное сложение дробей |
| `fraction_multiplication` | Путаница × и + |
| `division_error` | Ошибка деления дробей |
| `decimal_place` | Ошибка в разрядах |
| `unit_conversion` | Несогласованные единицы |
| `misread_condition` | Неверно прочитано условие |
| `calculation_error` | Ошибка в одном шаге |

Для каждой классификации возвращаются: `error_type`, `confidence`, `reason`, `detected_by`.

---

### 4. Библиотека шаблонов обратной связи

Каждый шаблон (`services/feedback_templates.py`) содержит:

- **rule** — краткое правило;
- **direction** — направление решения (без финального ответа);
- **reflection** — вопрос для самопроверки;
- **quality_note** — критерий «не спойлерит».

Пример фрагмента диалога:

> **Ученик:** `5/12` (при задаче `1/2 + 1/4`, верно `3/4`)  
> **Бот:** Тип: *Приведение к общему знаменателю*  
> Правило: сначала ОЗ, затем числители…  
> Подумай: какой общий знаменатель у дробей?  
> 💡 Подсказка к задаче: Приведи к знаменателю 4.  
> 🔁 Нажми «Аналогичная задача» для закрепления.

---

### 5. Снижение повторяемости ошибки (до/после)

Таблица `error_learning`:

- `times_seen` — сколько раз встречался тип ошибки;
- `times_repeated` — повторы после первого раза;
- `feedback_shown` — сколько раз показана ОС;
- `attempts_after_feedback` / `correct_after_feedback` — попытки после ОС.

**Показатель:** `times_repeated / times_seen` — чем ниже после серии занятий, тем эффективнее ОС.

---

### 6. Улучшение на аналогичных задачах

После ошибки ученик нажимает **«Аналогичная задача»** — выбирается задание той же сложности с пересекающимся `error_patterns`.

Метрики:

- `similar_attempts`, `similar_correct`;
- **% успеха на аналогичных** = `similar_correct / similar_attempts`.

Отображается в **📊 Статистика** и в сообщении при верном ответе после закрепления.

---

### 7. Качество объяснений (экспертная оценка)

Рекомендуемая шкала для преподавателя / анкеты учеников (1–5):

| Критерий | Вопрос |
|----------|--------|
| Понятность | Понятно ли правило своими словами? |
| Полезность | Помогло ли найти следующий шаг? |
| Без спойлера | Нет ли готового числового ответа? |
| Мотивация | Хочется ли попробовать снова? |

Шаблоны изначально проектируются с полем `quality_note` и без подстановки `task["answer"]` в текст ОС.

---

### 8. Примеры типичных ошибок по темам

**Дроби:** сложение без ОЗ, путаница × и +.  
**Арифметика:** порядок действий (слева направо вместо приоритета).  
**Текстовые:** неверные единицы, неверно выбранная операция.

### 10. Рекомендации для внедрения

1. Проводить 2–3 занятия с фиксацией одной темы для накопления статистики.

4. Проводить экспертную оценку 10–15 диалогов из `feedback_log`.
